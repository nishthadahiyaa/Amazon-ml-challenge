# Business Entity Resolution — ML Challenge 2026

Python implementation using only the supplied business data. Tested with Python
3.14.3; exact installed dependency versions are in `requirements.txt`.

## Required submission structure

```
output/
  matching_results.tsv
  candidate_pairs.tsv
code/business_entity_resolution/
  src/
  README.md
  requirements.txt
Documentation_template.md
```

The original `student_resource/` dataset and template remain unchanged. The filled
methodology document lives at the workspace root with the required filename.

## Setup

Run these commands from the workspace root (or extracted submission root). Supply
`--data /path/to/dataset` if the data is elsewhere.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r code/business_entity_resolution/requirements.txt
```

## Reproduce training and validation

```sh
.venv/bin/python code/business_entity_resolution/src/pipeline.py prepare --sample-size 4000
.venv/bin/python code/business_entity_resolution/src/pipeline.py train
```

Preparation scans the full reference file using a seeded uniform reservoir, then
searches both full training vendor files. It caches the final top-120 candidate set
per reference in `artifacts/training_candidates.json`. Training uses 60% of reference
entities; 20% tune the threshold and 20% form a development holdout excluded from fitting and threshold tuning. IDs determine
only reproducible splits and output identity; they are not matching features.
A check rejects true vendor links crossing split groups. All retrieved negatives are
used. True matches missed by blocking are counted as false negatives in evaluation.

The model is a histogram gradient-boosted classifier with 36 name/address comparison
features, trained for 160 iterations. Threshold selection maximizes competition
macro F0.5 over reference entities, including singleton credit. Results are saved in
`reports/model_metrics.json`, errors in `reports/model_errors.tsv`, and the fitted
model with its threshold in `artifacts/model.pkl`. Load only locally trusted pickle files.

## Generate the two required test outputs

```sh
.venv/bin/python code/business_entity_resolution/src/pipeline.py predict --reference-batch-size 10000
.venv/bin/python code/business_entity_resolution/src/validate_submission.py --matching output/matching_results.tsv --candidate output/candidate_pairs.tsv --test-dir student_resource/dataset/test --check-ids
```

Every reference, including France and singletons, gets a row. Final candidate IDs
are exported immediately before classifier inference, and matches are a subset.
Files use temporary names until prediction completes. Only the final matching TSV
is uploaded to the leaderboard. No competition upload is automated.

**Current scaling limitation:** prediction bounds memory by processing reference
batches and rescans the full vendor files for each batch. With 1.73M references,
10,000 per batch means 174 vendor scans and may take many hours. Increasing the batch
size trades memory for runtime. The broad-block cap is counted within a reference
batch, so batch size can also change retrieval; keep it fixed for comparisons.
The sampled validation does not establish full-scale blocking quality. A persistent
on-disk inverted index and globally measured block frequencies are the next scaling
improvement before a competitive full inference run. No full test inference has
been completed yet.

## Tests and initial analysis

```sh
.venv/bin/python -m unittest discover -s code/business_entity_resolution/src -p 'test_*.py'
.venv/bin/python code/business_entity_resolution/src/analyze.py
```

`analyze.py` preserves the original exact-match baseline for comparison. The new
pipeline uses `preprocessing.py`, including a fix to preserve Unicode combining marks.
The synthetic integration test checks training, prediction, France support, empty
candidates, and the official validator; its synthetic scores are not model quality evidence.

## Package after full inference

Fill in team details in `Documentation_template.md`, then run:

```sh
.venv/bin/python code/business_entity_resolution/src/package_submission.py --team-name YOUR_TEAM
```

Packaging requires both real output files and checks them before writing
`YOUR_TEAM_submission.zip`. It includes the required code, pinned dependencies,
outputs and methodology. Models can be regenerated by the prepare/train commands;
raw datasets, caches and the virtual environment are excluded.

## Source modules

- `preprocessing.py`: Unicode-safe normalization, legal suffix handling, retrieval keys.
- `blocking.py`: streaming vendor retrieval and bounded top-k candidates.
- `features.py`: fuzzy name/address comparisons, numeric agreement and missingness.
- `evaluation.py`: reference-level macro F0.5 and diagnostics.
- `pipeline.py`: prepare, train and predict entry points.
- `validate_submission.py`: unchanged supplied validator.
- `package_submission.py`: validated archive creation.
- `test_*.py`: metric edge cases and end-to-end contract tests.

Original fitted model parameters are covered by `MODEL_LICENSE` (MIT); third-party
dependencies keep their own licenses. No external entity lookup, geocoding, pretrained
model or business augmentation is used.
No automatic transitive closure is applied: uncertain links do not propagate across
businesses. France transfer and cross-script matching remain areas for improvement.

## Measured development result

The upgraded run achieves macro F0.5 **0.8642** on the same 795 development holdout
references, versus **0.8329** for v1. Precision is **97.01%**, recall **76.41%**, and
candidate recall **85.14%**. Threshold **0.61** was selected on 782 separate tuning
references. The default model and cache in `artifacts/` are now v2.

V2 adds address-token/number and address-token-pair retrieval, phonetic name-number
keys, Latin accent folding for comparisons, fuzzy token coverage and script indicators.
It retains up to 120 candidates. The feature-only ablation scored **0.8400** using
v1 candidates, indicating that broader retrieval supplies most of this improvement.

Previous artifacts and source are retained in `artifacts/v1/`, and new artifacts in
`artifacts/v2/`. Run `src/compare_models.py` from the workspace root to reproduce the
paired development comparison using those caches. These are reused development
results, not a fresh test/leaderboard score; new validation and country-transfer
checks remain necessary. Full test inference is still outstanding.
